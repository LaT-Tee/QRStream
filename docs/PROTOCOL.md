# QX4 帧协议规范

本文档描述 QRStream 的空中帧格式与编解码算法，足以让第三方独立实现兼容的发送端或接收端。参考实现：[`src/codec.js`](../src/codec.js)、[`src/sender-core.js`](../src/sender-core.js)。

## 1. 总览

```
文件/文本 ──► [可选 deflate / LZMA] ───► 数据包 ──► 切成 K 个 C 字节源块
                                                          │
                       系统帧 SEQ=0..K-1（源块原样） ◄──────┤
                       冗余帧 SEQ≥K（若干源块的 XOR）◄──────┘   ← GF(2) 随机线性喷泉码
                                    │
                         Base45 → QR（Alphanumeric 模式）→ 屏幕 ──► 摄像头
```

接收端收到**任意** K + ε 个线性无关的帧即可还原（ε 平均约 1.6），漏掉的帧不需要等下一轮重播。

## 2. 数据包（Packet）

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0 | 4 | `metaLen`，大端 uint32 |
| 4 | metaLen | meta，UTF-8 JSON |
| 4 + metaLen | 其余 | 数据（可能已压缩，见 `z`） |

meta 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `t` | `"text"` \| `"file"` | 类型 |
| `name` | string | 文件名（文本为 `text.txt`） |
| `mime` | string | MIME 类型 |
| `z` | `false` \| `true` \| `"lzma"` | 压缩方式：`false` 不压缩；`true` 为 zlib 格式 deflate（`CompressionStream('deflate')`）；`"lzma"`（1.4.0 起）为 LZMA-alone 格式（`.lzma`：13 字节头 + LZMA 流，与 7-Zip / xz-utils `--format=lzma` 相同），发送端用 LZMA-JS 第 3 级压缩。1.3.0 及更早的接收端不认识 `"lzma"`，会报解压失败 |
| `len` | number | **解压后**数据的字节数，用于校验 |

数据包总长记为 `LEN`。选取块大小 `C`（4 的倍数，≥ 52），`K = ceil(LEN / C)`，末块补 0 到 `K × C`。

`CRC` = CRC-32/ISO-HDLC（与 zlib 相同）作用于数据包前 `LEN` 字节，8 位大写十六进制。

## 3. 帧文本

```
QX4:<SID>:<K>:<LEN>:<CRC>:<SEQ>:<FCK>:<PAYLOAD>*
```

| 字段 | 格式 | 说明 |
|---|---|---|
| `SID` | 4 位 `[0-9A-Z]` | 会话 ID，每次生成随机 |
| `K` | 十进制 | 源块数，1 ≤ K ≤ 20000 |
| `LEN` | 十进制 | 数据包长度；必须满足 `ceil(LEN / C) == K` |
| `CRC` | 8 位大写 hex | 整包 CRC32 |
| `SEQ` | 十进制 | 帧序号，见第 4 节 |
| `FCK` | 8 位大写 hex | **本帧载荷**（解码后的 C 字节）的 CRC32 |
| `PAYLOAD` | Base45（RFC 9285） | C 字节载荷，长度 = 1.5 × C 字符 |
| `*` | 字面量 | 结束符。Base45 字母表含空格，结束符防止扫码库裁掉末尾空格 |

所有字符都属于 QR Alphanumeric 字符集（`0-9 A-Z 空格 $ % * + - . / :`），因此整帧以 Alphanumeric 模式编码，每字节约 8.25 bit，比 Base64 + Byte 模式（约 10.7 bit）省约 23%。

解析时按前 7 个 `:` 切分（Base45 本身含 `:`），再去掉末尾 `*`。

**兼容性**：接收端同时接受 `QX3:` 前缀，此时 `FCK` 为 4 位 hex（CRC32 的低 16 位），其余相同。

## 4. 喷泉码

### 4.1 系统帧

`SEQ < K`：载荷就是第 `SEQ` 个源块。

### 4.2 冗余帧

`SEQ ≥ K`：载荷 = `rowBits(SID, SEQ, K)` 选中的所有源块按字节 XOR。每个源块被选中的概率为 1/2（稠密随机 GF(2) 编码）。

`rowBits` 必须与参考实现逐位一致：

```js
function rowBits(sid, seq, K) {
  // 1) FNV-1a 32 位哈希 "SID:SEQ" 作为种子
  let h = 2166136261;
  const s = sid + ':' + seq;
  for (let i = 0; i < s.length; i++) { h ^= s.charCodeAt(i); h = Math.imul(h, 16777619); }
  // 2) mulberry32 生成 ceil(K/32) 个 32 位字，第 c 位（字 c>>5 的第 c&31 位）= 是否选中源块 c
  let a = h | 0;
  const W = (K + 31) >>> 5, bits = new Uint32Array(W);
  for (let w = 0; w < W; w++) {
    a = (a + 0x6D2B79F5) | 0;
    let t = Math.imul(a ^ (a >>> 15), 1 | a);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    bits[w] = (t ^ (t >>> 14)) >>> 0;
  }
  // 3) 清掉 ≥K 的位；若全 0，强制选中 seq % K
  if (K & 31) bits[W - 1] &= (1 << (K & 31)) - 1;
  if (bits.every(x => x === 0)) { const c = seq % K; bits[c >>> 5] |= 1 << (c & 31); }
  return bits;
}
```

### 4.3 发送顺序

先按 `SEQ = 0, 1, …, K-1` 播放一轮系统帧，之后 `SEQ = K, K+1, …` 无限播放冗余帧。用户可指定"只播帧"列表（仅系统帧编号）做定向补发。

### 4.4 解码（参考实现）

增量 GF(2) 高斯消元，行阶梯形：

1. 每收到一帧：先用位掩码一次性剥离所有已知源块（只 XOR 载荷），再从最低位起用已有主元行约简；
2. 剩余非零 → 以最低位为主元加入；只剩一位 → 该源块直接已知；全零 → 线性相关，丢弃；
3. 秩达到 K → 从高列到低列回代，得到全部源块；
4. 拼包，校验整包 CRC，解析 meta，按需解压，校验 `len`。

复杂度：每帧 O(r · (K/32 + C/4))，r 为当前秩；回代 O(K² · C / 8) 最坏。参考实现把消元和回代都放在 Web Worker 中。

## 5. RGB 三通道模式

- 一张图的 R、G、B 三个通道各承载一个独立的 QR 帧，依次放置连续 3 个 SEQ；
- 每个通道：深色模块 = 0，浅色模块 = 255。8 种组合色（黑、红、绿、蓝、青、品红、黄、白）；
- 同一会话的 QR **版本固定**（按 `SEQ = 9999999` 的最长帧计算），保证三层模块网格完全对齐；
- 接收端分别取出每个通道作为灰度图识别；失败时再用 `1.6·c − 0.3·(o₁ + o₂)` 做简单的串色补偿后重试。

## 6. 静区与渲染

- 静区 4 模块；
- 渲染时 1 模块 = 1 像素绘制，再按**整数倍**最近邻放大，保证边缘锐利；
- 帧切换跟随 `requestAnimationFrame`，按屏幕刷新次数计数（每张显示 `round(间隔 / 刷新周期)` 次刷新），不按毫秒累加，避免个别帧变短引起混帧；默认间隔 66 ms。

## 7. QX5 彩格码（自定义码型）

QX5 不再用 QR 承载帧，而是自定义的彩色格子码。喷泉码层（第 2、4 节：数据包、`K`、`C`、`rowBits`、系统帧/冗余帧）**完全相同**，只是「一个符号怎么画到屏幕上」不同：一张图分成 `T` 个等大的**块**，每块独立承载一个喷泉码符号（`SEQ` + `C` 字节载荷）。参考实现：[`src/grid-code.js`](../src/grid-code.js)。

设计动机（仿真依据见 [SIMULATION.md](SIMULATION.md)）：

- 屏幕换帧与摄像头卷帘快门不同步时，一张照片的上下两部分可能属于两帧（混帧）。QR 只要有一行混帧就整码作废；QX5 每块自带 `SEQ` 和 CRC，过渡带里的块丢掉，其余块照常可用。
- 每格 RGB 各通道 2 或 4 级亮度，即 8 / 16 / 32 / 64 色，用软判决 + LDPC 纠错，不靠二值化。

### 7.1 版面

单位为**格**，`cols`、`rows` 均为 31..255 的奇数；行 `r`、列 `c` 从 0 开始，格下标 `k = r·cols + c`。外加 2 格白色静区。

| 区域 | 位置 | 内容 |
|---|---|---|
| 定位块 | 四角各 7×7 | 同心方块：到中心的切比雪夫距离 `d = max(|r−3|,|c−3|)`，`d = 3` 或 `d ≤ 1` 为黑，`d = 2` 为白。任何方向过中心的截线都是 1:1:3:1:1 |
| 隔离带 | 定位块内侧 1 格（构成 8×8 角块） | 白 |
| 时钟线 | 第 3 行、第 `rows−4` 行的第 8..`cols−9` 列；第 3 列、第 `cols−4` 列的第 8..`rows−9` 行 | 坐标为偶数时黑、奇数时白。它们正好连接相邻定位块的中心 |
| 导频 | 其余格中满足 `r mod 4 = 1` 且 `(c + 2·((r>>2) & 1)) mod 4 = 1` 的格（约 1/16） | 颜色已知，见 7.3 |
| 元信息 | 其余格（非定位/隔离/时钟/导频）按行扫描的**最前 120 格**和**最后 120 格** | 两份相同的元信息，见 7.4 |
| 数据块 | 剩余格 | 见 7.5 |

### 7.2 色阶与颜色

每格三个通道独立取色阶：通道级数 `L ∈ {2, 4}`，2 级取值 `{0, 255}`，4 级取值 `{0, 85, 170, 255}`。每格比特数 `bpc = Σ log2(L_ch)`。4 级通道用格雷码：2 位 `(b0 b1)`（b0 为先发的位）→ `g = 2·b0 + b1`，级 `l = g ^ (g >> 1)`。格内比特顺序：R 的位、G 的位、B 的位。

参考实现提供四个档位：稳 8 色（2,2,2）码率 2/3、标准 16 色（2,4,2）码率 3/4、快 32 色（4,4,2）码率 2/3、极速 64 色（4,4,4）码率 3/4。

### 7.3 导频

`hash3(r, c, k)`（参考实现中的整数哈希，三个参数各 +1 后乘大素数异或，再做 murmur 式混合）为每个导频格每个通道确定色阶：

- **A 类**导频（`((r>>2) + (c>>2))` 为偶数）：`hash3(r,c,ch) & 1 ? L_ch − 1 : 0`，只用各通道的最暗/最亮级，与色阶配置无关，读元信息时只用它们；
- **B 类**导频：`hash3(r,c,ch) mod L_ch`，覆盖全部色阶。

接收端在每个块（外扩 `ceil(tile/3)` 格）的范围内用导频做最小二乘：对每个通道拟合 `t = a·R + b·G + c·B + d`（`t = 级/(L−1)`，R/G/B 为摄像头观测值），一次性校正串色、白平衡、暗角；再用导频算出各级的中心和噪声方差，得到每个比特的对数似然比。

### 7.4 元信息

22 字节 + CRC32（大端，覆盖前 22 字节）：

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0 | 1 | `0x55` |
| 1 | 4 | `SID`（4 个 ASCII 字符） |
| 5 | 3 | `K`（大端） |
| 8 | 4 | `LEN` |
| 12 | 4 | 整包 `CRC`（数值） |
| 16 | 2 | `C`（每块载荷字节） |
| 18 | 1 | `cols` |
| 19 | 1 | `rows` |
| 20 | 1 | 位 0/1/2：R/G/B 是否 4 级；位 3..5：码率下标（`[1/3, 2/5, 1/2, 3/5, 2/3, 3/4, 4/5]`）；位 6：数据块纠错码，1 = LDPC，0 = 卷积码（1.1.0） |
| 21 | 1 | `tile`（块的目标边长，格） |

固定用 8 色（每通道 2 级）、加扰种子 1000，用 7.6 节的**卷积码**编码成 120 格 × 3 位 = 360 位（元信息短，卷积码更合适；与数据块用哪种码无关）。

### 7.5 数据块

1. 把所有数据格按**希尔伯特曲线**（边长取不小于 `max(cols, rows)` 的 2 的幂，标准 d→(x,y) 映射，落在版面外的点跳过）排序；
2. 块数 `T = max(1, round(D / max(64, 0.8·tile²)))`（`D` 为数据格数），每块 `n = floor(D / T)` 格，按顺序依次切分；多出的不足一块的格子填伪随机色；
3. 每块信息位：`SEQ`（32 位）‖ 载荷（`C` 字节）‖ `CRC32(SID 的 4 个 ASCII 字节 ‖ SEQ ‖ 载荷)`，共 `nInfo = 64 + 8C` 位；CRC 绑定会话号，别的会话的块不可能通过校验；
4. `C = ⌊(⌊n·bpc·R⌋ − 64) / 8⌋`（卷积码为 `− 70`），再向下取 4 的倍数（`R` 为码率）。

第 `j` 块（0 起）承载本张图的第 `j` 个 `SEQ`，加扰种子为 `j + 1`。发送端第 `p` 张图依次放 `SEQ = p·T … p·T+T−1`。

### 7.6 信道编码

数据块默认用 **LDPC**（元信息字节 20 位 6 = 1），元信息和 1.1.0 发送端的数据块用卷积码。两种码共用交织与加扰：码字第 `i` 位放到发送位置 `π(i)`（下面第 3 条），再异或加扰序列（第 4 条）。

**LDPC（IRA 结构）**：码长 `n = 格数·bpc`、信息长 `k = nInfo`、校验数 `m = n − k`，码字 = 信息位 ‖ 校验位。

- 校验矩阵右半部分是双对角：第 `j` 个校验位连到第 `j`、`j+1` 个校验方程，编码就是累加 `p_j = p_{j−1} ⊕ (第 j 个方程里信息位的异或)`；
- 信息位度数按码率选：`k/n < 0.58` 用循环序列 `4,4,4,4,10`，`< 0.7` 用 `3,3,6`，否则 `3,3,3,3,8`（第 `i` 个信息位取第 `i mod 长度` 个）；
- 连边：把每个方程编号重复填成长为「度数总和」的牌堆（第 `t` 张 = `t mod m`），用 xorshift32（种子 `n·7919 ⊕ k`）做 Fisher–Yates 洗牌；信息位依次从牌堆当前位置往后找最多 400 张，取第一张「不与本变量已选方程重复、且与已选方程组成的方程对未被用过」的（避开 4 环；双对角相邻方程对预先算作已用），找不到就放宽 4 环约束；
- 译码：分层归一化最小和（系数 0.75），最多 40 轮，所有方程满足即停；参考实现在第 8 轮后仍有 >15% 方程不满足时放弃该块。

收发双方必须逐位一致地构造同一张图；参考实现 `ldpcCode(n, k)`。

**卷积码**（元信息；1.1.0 的数据块）：

1. **卷积码**：约束长度 7、码率 1/3，生成多项式八进制 133 / 171 / 165。寄存器 `reg = (u << 6) | s`，第 k 路输出 = `popcount(reg & G_k) & 1`，下一状态 `(u << 5) | (s >> 1)`，末尾补 6 个 0 归零；
2. **速率匹配（循环缓冲）**：母码按「第 0 路全部（时间顺序）→ 第 1 路 → 第 2 路」排列，第 1、2 路的时间顺序按 `frac(t·0.6180339887…)` 升序。取前 `n_tx = 格数·bpc` 位，不够就从头循环重复；
3. **交织**：长度 `n_tx` 的伪随机置换（xorshift32，种子 `n_tx·2654435761`，Fisher–Yates），第 `i` 个发送位放到位置 `π(i)`；
4. **加扰**：位置 `i` 的位再异或 xorshift32 序列（种子由块号和 `n_tx` 决定）的最高位，避免补零数据画成大片同色。

接收端：逐格软判决 → 去加扰 → 反交织 → LDPC 译码（卷积码则按循环缓冲累加到母码位置，被删的位 LLR = 0，再软判决 Viterbi）→ 校验 CRC。

### 7.7 接收端定位（参考实现）

1. 亮度 `Y = (R + 2G + B)/4`，局部均值的 0.9 倍以下为黑；逐行找 1:1:3:1:1（两侧还要有白），再做竖向、斜向交叉验证，聚类得到定位块中心；
2. 取模块大小一致、面积最大的凸四边形；
3. 四种方向各试一次：沿相邻定位块中心连线读时钟线，数黑白段得到 `cols`、`rows`（`段数 + 8`，对边互为备份）；用定位块中心 + 时钟格中心做最小二乘单应，再在预测位置附近找每个时钟格的明暗中心精修一次；
4. 用 A 类导频的校色残差选方向（只有正确方向能和已知颜色对上），读元信息；同一会话内单张读不出元信息时，沿用之前读到的；
5. 每格采样中心及 ±0.2 格四点的平均，逐块校色、软判决、译码。

### 7.8 节奏

换帧对齐屏幕刷新（按刷新次数计数，不按毫秒累加）。默认 66 ms（60 Hz 下 4 次刷新）：30 fps 摄像头下每张图都至少有一次完整曝光。
